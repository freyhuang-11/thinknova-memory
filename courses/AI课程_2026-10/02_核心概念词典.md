# 第 2 课 · 核心概念词典（Skills / Agent / Harness / RAG / MCP / Memory …）

> 目标：这些词以后在任何 AI 产品文档里看到，都能立刻对上「它在系统的哪一层、解决什么问题」。

---

## 2.1 一张总图：AI 系统的分层

```
┌─────────────────────────────────────────────────────────────┐
│  应用层   ThinkNova 视频 Agent / 你的业务工作流                  │
├─────────────────────────────────────────────────────────────┤
│  编排层   Workflow（写死的步骤）  ／  Agent（自主决策）           │
│           Sub-agent（子智能体）  ／  多 Agent 协作                │
├─────────────────────────────────────────────────────────────┤
│  能力层   Tools（工具） · MCP（工具接入协议） · Skills（技能包）    │
├─────────────────────────────────────────────────────────────┤
│  上下文层 System Prompt · 规则文件 · Memory · RAG 检索结果         │
├─────────────────────────────────────────────────────────────┤
│  Harness  权限 · 沙箱 · Hooks · 上下文压缩 · 会话管理              │
├─────────────────────────────────────────────────────────────┤
│  模型层   LLM（Claude / GPT / DeepSeek …）· 生图 · 生视频 · TTS    │
└─────────────────────────────────────────────────────────────┘
```

## 2.2 逐个定义（标准定义 + 大白话 + 例子）

### ① Prompt（提示词）／ System Prompt（系统提示词）
- **定义**：输入给模型的指令文本。System Prompt 是每次调用都固定带上的「人设 + 规则」部分，User Prompt 是本次的具体请求。
- **大白话**：给员工的岗位说明书（System）+ 今天的任务单（User）。
- **例**：ThinkNova 的编剧 `systemPrompt` 规定「台词句数跟镜头数一致」，商家填的商品名、卖点是 User 部分。

### ② Context Engineering（上下文工程）
- **定义**：设计「在模型调用的那一刻，上下文窗口里放什么、按什么顺序、放多少」的工程方法。是 Prompt Engineering 的升级版。
- **大白话**：不只是「话怎么说」，而是「这次开会桌上摆哪些资料」。
- **三个原则**：相关的才放；重要的放前面；越短越好（每多一个字都在稀释注意力）。

### ③ Tool（工具）／ Function Calling
- **定义**：以结构化 schema 声明给模型的可调用能力（名称、描述、参数）。模型输出调用请求，由外部执行。
- **例**：`Read`、`Bash`、`WebSearch`、调用 ThinkNova 后台接口拉 config。

### ④ Agent（智能体）
- **定义**：在循环中自主选择工具、根据结果调整计划、直到完成目标的 LLM 系统。
- **与 Workflow 的区别**（Anthropic《Building Effective Agents》的经典划分）：

| | Workflow 工作流 | Agent 智能体 |
|---|---|---|
| 步骤由谁定 | **人写死**（代码 / 流程图） | **模型自己决定** |
| 可预测性 | 高 | 低 |
| 适合 | 步骤固定、要求稳定（如出片管线） | 开放问题、步骤未知（如排查 bug） |
| 成本 | 低、可控 | 高、波动 |
| ThinkNova 例子 | 资料 → 编剧 → 分镜 → 首帧 → 视频，六步固定 | Claude Code 帮你排查「为什么这单没声音」 |

> 🔴 **选型原则**：能用 Workflow 就别用 Agent。只有当「下一步做什么取决于上一步的结果、且无法预先穷举」时，才上 Agent。

### ⑤ Sub-agent（子智能体）
- **定义**：主 Agent 派出去执行子任务的独立 Agent，**有自己独立的上下文窗口**，只把结论交回主 Agent。
- **价值**：① 隔离上下文（搜 50 个文件的过程不污染主对话）② 并行 ③ 专精（审查 agent、测试 agent）。
- **风险**：子 agent 的结论可能是错的——**转述前要自己验证**（ThinkNova 铁律：verify-before-relaying）。

### ⑥ Skill（技能）
- **定义**：一个打包好的「能力文件夹」：一个 `SKILL.md`（名称 + 何时使用的描述 + 操作步骤），可附带脚本、模板、参考资料。
- **核心机制 —— 渐进式披露（Progressive Disclosure）**：
  1. 平时上下文里**只放每个 skill 的名字和一句描述**（几十个 token）
  2. 任务匹配时，才加载完整 `SKILL.md`
  3. 需要时，再读 skill 目录下的脚本 / 参考文件
- **大白话**：员工手册的目录常驻脑中，用到哪章才翻哪章。
- **与 Prompt 的区别**：Prompt 每次都占上下文；Skill 按需加载，可以装几十上百个而不撑爆上下文。
- **与 Tool 的区别**：Tool 是「一个动作」，Skill 是「一套做事的方法 + 配套工具」。
- **例**：ThinkNova 用的 `xhs-note`（小红书笔记四柱：选题→标题→配图→文案）、`hyperframes`（视频/动画的强制入口）。

### ⑦ Harness（运行框架 / 外壳）
- **定义**：包裹模型、让它能作为 Agent 运行的那层软件：上下文组装、工具执行、权限审批、沙箱、Hooks、记忆加载、上下文压缩、会话管理。
- **大白话**：模型是「大脑」，Harness 是「身体 + 公司制度」。同一个模型放进不同 Harness，表现差别很大。
- **例**：**Claude Code 和 Codex 本质上都是 Harness**。Claude Agent SDK / Codex SDK 让你用同一套 Harness 搭自己的 Agent。
- **Harness 负责的事**（考点）：

| 能力 | Claude Code 里叫 | Codex 里叫 |
|---|---|---|
| 规则文件 | `CLAUDE.md` | `AGENTS.md` |
| 权限 / 审批 | permissions + 权限模式 | approval policy |
| 隔离 | sandbox | sandbox mode |
| 事件钩子 | Hooks | Hooks（`hooks.json`） |
| 工具扩展 | MCP / Skills / Plugins | MCP / Skills |
| 上下文压缩 | `/compact`、自动压缩 | `/compact` |

### ⑧ MCP（Model Context Protocol，模型上下文协议）
- **定义**：Anthropic 提出的开放协议，统一「AI 应用 ↔ 外部工具/数据源」的接口。一个 MCP Server 暴露一组工具/资源，任何支持 MCP 的客户端（Claude Code、Codex、Cursor…）都能接。
- **大白话**：AI 世界的 USB-C。写一次接口，到处能插。
- **例**：GitHub MCP、Google Drive MCP、Gmail MCP、浏览器控制 MCP。

### ⑨ RAG（Retrieval-Augmented Generation，检索增强生成）
- **定义**：生成之前，先从外部知识库**检索**相关片段，把片段放进上下文，再让模型基于这些片段回答。
- **标准流程**：

```
离线：文档 → 切块（Chunking）→ 向量化（Embedding）→ 存入向量库
在线：用户问题 → 向量化 → 相似度检索 Top-K → （可选）重排序 Rerank
      → 把片段 + 问题拼进提示词 → 模型生成 → 附引用来源
```

- **解决什么**：① 模型知识过时 ② 私有知识模型不知道 ③ 减少幻觉（有出处可查）
- **常见坑**：切块太碎丢上下文；检索到旧版本文档（新旧并存）；Top-K 太多稀释注意力。
- **Agentic RAG / Agentic Search**：不预先建向量库，让 Agent 自己用 `grep`、`find`、读文件去「搜」。Claude Code 就是这种思路——代码库场景下往往比向量检索更准。
- **ThinkNova 对应**：
  - 商家选的**案例库 / 场景表**被注入编剧上下文 = 一种结构化检索增强
  - 我们的记忆库「路由表：做什么事先开哪个文件」= 人工设计的检索索引

### ⑩ Memory（记忆）
- **定义**：跨会话保留信息的机制。模型本身不记得，记忆是 Harness 在每次会话开始时**把记忆文件读进上下文**。
- **分类**：

| 类型 | 生命周期 | 例子 |
|---|---|---|
| 短期记忆 | 本次会话 | 对话历史、工具结果 |
| 长期·规则记忆 | 永久，人写 | `CLAUDE.md` / `AGENTS.md` |
| 长期·自动记忆 | 永久，AI 自己写 | Claude Code auto memory 的 `MEMORY.md` + 主题文件（本仓库就是这种） |
| 外部知识 | 按需检索 | RAG、文档库 |

- 详见第 5 课。

### ⑪ Hooks（钩子）
- **定义**：在 Agent 生命周期的特定事件（工具调用前/后、会话开始、提交提示词时、结束时）**自动执行的脚本**，由 Harness 执行，不靠模型自觉。
- **大白话**：规则写在提示词里，模型「可能」遵守；写成 Hook，就是「一定」执行。
- **例**：每次编辑完文件自动跑格式化；禁止 `rm -rf`；会话开始自动 `git pull` 记忆库。

### ⑫ Plan Mode（计划模式）
- 先让 Agent 只读、只调研、写方案，人审批后再动手。对应 ThinkNova 铁律「先讨论拍板再让我动手」。

### ⑬ Eval（评测）
- **定义**：用固定样本集衡量 AI 输出质量的方法。改提示词前后跑同一批样本对比。
- **ThinkNova 对应**：「烧单验证」= 人工 eval；「修复前基线」= eval 的 baseline；「逐帧通看」= 评测标准。

### ⑭ Guardrails（护栏）
- 限制模型输出范围的规则：负面词、内容策略、输出格式校验（如编剧输出的 `lineValidation` 字数校验）。

## 2.3 概念之间的关系（考试必背）

- **Skill 用 Tool 干活**，Tool 可以由 **MCP** 提供。
- **Agent 在 Harness 里跑**，Harness 读 **Memory** 和规则文件组装上下文。
- **RAG 是往上下文里塞知识的一种方式**，Memory 是另一种。
- **Workflow 可以包含 Agent 节点**：ThinkNova 管线整体是 Workflow，但「编剧」这一步内部是模型自主生成。
- **Hook 管「一定发生」，Prompt 管「最好发生」**。

**课后练习**：拿你最近一次用 AI 做的事，按 2.1 的分层图标出：哪些在上下文层、哪些在能力层、哪些在 Harness 层。
