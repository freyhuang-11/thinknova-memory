# 第 1 课 · AI 是怎么工作的（从模型到 Agent）

> 目标：学完能用自己的话讲清「一次对话里到底发生了什么」，并且知道 AI 出错时该往哪一层查。

---

## 1.1 大语言模型（LLM）的本质：下一个 token 预测器

| 概念 | 一句话定义 | 实际影响 |
|---|---|---|
| **Token** | 模型读写的最小单位（中文约 1 字 ≈ 1–2 token，英文约 1 词 ≈ 1.3 token） | 计费、上限、速度都按 token 算，**不按字数** |
| **上下文窗口（Context Window）** | 模型一次能「看见」的全部 token：系统提示 + 历史对话 + 文件 + 工具结果 | 窗口外的东西，模型**完全不知道**；窗口快满时质量会下降 |
| **无状态（Stateless）** | 每次调用都是全新的，模型本身不记得上一次 | 所谓「记忆」都是**外部系统把内容重新塞进上下文** |
| **采样 / 温度（Temperature）** | 从概率分布里挑下一个 token 的随机程度 | 温度高 = 更多样也更不稳；同一提示词跑两次结果不同是正常的 |
| **训练截止（Knowledge Cutoff）** | 模型知识的时间边界 | 新产品、新价格、新配置，**必须靠工具现查**，不能靠模型记忆 |
| **幻觉（Hallucination）** | 模型编出看起来合理但不真实的内容 | 所以要有「证据标准」：结论必须能回到真实数据 |

**关键认知**：模型只做一件事——**根据它眼前的上下文，生成最可能的下一段文字**。
它能不能做对，取决于两件事：① 模型本身的能力 ② **你给它的上下文质量**。第 ② 件是我们能控制的，这就是「上下文工程」。

## 1.2 从「聊天」到「Agent」：工具调用（Tool Use）

纯模型只能输出文字。让它「做事」的办法是 **工具调用**：

```
1. 我们告诉模型：你有这些工具（读文件 / 跑命令 / 搜索 / 调 API），每个工具的参数是什么
2. 模型输出的不是答案，而是一条结构化指令：「调用 Read，参数 file_path=xxx」
3. 外部程序（Harness）真的去执行这条指令，把结果塞回上下文
4. 模型看到结果，决定下一步：再调工具，或者给出最终答案
```

这个循环就是 **Agent Loop（智能体循环）**：

```
   ┌──────────────────────────────────────────────┐
   │  用户目标                                      │
   └──────────────┬───────────────────────────────┘
                  ▼
   ┌──────────────────────────┐
   │ 模型思考：下一步做什么？    │◄─────────────┐
   └──────────────┬───────────┘              │
                  ▼                           │
        需要工具？──是──► Harness 执行工具 ──► 结果写回上下文
                  │
                  否
                  ▼
           输出最终结果
```

> **Agent 的定义**：一个能在循环里**自主决定调用哪些工具、调用几次、何时停下**的模型系统。
> 关键词是「自主决定」——如果每一步都是写死的，那叫 Workflow（工作流），不叫 Agent。

## 1.3 一次 Claude Code / Codex 会话里实际发生了什么

以「帮我修复登录页的 bug」为例：

| 步骤 | 谁在干活 | 发生了什么 |
|---|---|---|
| 1 | Harness | 组装上下文：系统提示 + `CLAUDE.md`/`AGENTS.md` 规则 + 记忆 + 可用工具列表 + 你的这句话 |
| 2 | 模型 | 决定先 `Grep` 搜 "login" |
| 3 | Harness | 检查权限（允许吗？要不要问用户？）→ 执行 → 结果回填 |
| 4 | 模型 | 读文件、定位问题、决定修改 |
| 5 | Harness | `Edit` 前触发 Hook（例如自动格式化）、检查权限 |
| 6 | 模型 | 跑测试验证 |
| 7 | 模型 | 汇报结果 |

**出错时往哪查**（这是本课最实用的一张表）：

| 现象 | 最可能的层 | 查什么 |
|---|---|---|
| 不知道项目规矩 | 上下文 | 规则文件写了吗？太长被忽略了吗？ |
| 用了过时的信息 | 记忆 / 知识截止 | 记忆里旧结论没删？该现查的没现查？ |
| 不敢做 / 一直问 | Harness 权限 | 权限配置、权限模式 |
| 乱做 / 做过头 | 提示词 + 权限 | 指令有歧义？权限给太宽？ |
| 多个不同模型报**同一个**错 | **提示词** | 不是模型的问题，是指令本身互相冲突（ThinkNova 实战结论，见第 6 课） |
| 越聊越笨 | 上下文窗口 | 太长了，该压缩或开新会话 |

## 1.4 推理（Reasoning / Thinking）

新一代模型会在回答前先「想」一段（Extended Thinking / Reasoning Effort）。

- **思考越多 ≠ 越好**：简单任务开高推理只是更慢更贵。
- **适合高推理**：架构设计、复杂 bug、多约束规划。
- **适合低推理**：改错别字、格式转换、批量重复操作。
- Claude Code 和 Codex 都能调推理强度（见第 3、4 课）。

---

## 1.5 本课小结

1. 模型是**无状态的 token 预测器**，一切「聪明」都来自上下文。
2. Agent = 模型 + 工具 + 循环 + 自主决策。
3. Harness 是包在模型外面的那层「操作系统」——上下文组装、工具执行、权限、钩子、记忆全在这一层。
4. 出了问题先分层：上下文？权限？提示词？模型？**别一上来就换模型**。

**课后练习**：打开 Claude Code，输入 `/context`，看看你的上下文窗口里现在装了什么、各占多少。
