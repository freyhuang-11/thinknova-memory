# 第 6 课 · 怎么搭建 AI Workflow（工作流）

> 目标：能把一件业务拆成 AI 工作流，知道每一步用什么模式、怎么验收、怎么控成本。

---

## 6.1 五种标准编排模式

（来自 Anthropic《Building Effective Agents》，业界通用叫法）

| 模式 | 结构 | 什么时候用 | ThinkNova 例子 |
|---|---|---|---|
| **① 提示链 Prompt Chaining** | A 的输出 → B 的输入 → C | 任务能拆成固定顺序的子步骤 | 编剧 → 分镜图 → 首帧 → 视频 |
| **② 路由 Routing** | 先分类，再分发给专门的处理器 | 输入类型差异大 | 按行业 × 场景选不同提示词模板；海报线 / 视频线分家 |
| **③ 并行 Parallelization** | 多个子任务同时跑，再汇总；或同一任务跑多次投票 | 子任务独立；需要多视角 | 一条片 5 个镜头并行生成；多个子 agent 同时调研 |
| **④ 编排者-执行者 Orchestrator-Workers** | 主模型动态拆任务、派给执行者、汇总 | 子任务数量和内容事先不确定 | 主 Agent 派子 Agent 分别查配置、查订单、查文档 |
| **⑤ 评估者-优化者 Evaluator-Optimizer** | 一个生成、一个打分，循环改进 | 有明确评判标准 | 编剧输出 → `lineValidation` 字数校验 → 不合格重试 |

在这五种之上，才是完全自主的 **Agent**。原则：**从最简单的模式开始，确有必要才加复杂度。**

## 6.2 搭建 Workflow 的七步法

### 第 1 步 · 定义终态（Done 长什么样）
- 写清「交付物是什么、谁验收、验收标准」。
- ❌「做个视频」 ✅「15 秒竖屏 9:16、台词字数在校验区间内、零字幕、人物与参考图一致、能直接发」

### 第 2 步 · 第一性拆解
- 把任务拆到不可再拆的事实，再从这些事实往上推步骤。
- 不要从「别人都这么做」起步。

### 第 3 步 · 每一步定「输入 / 输出 / 负责什么」
用表格写清，尤其是**边界**（这一步**不**负责什么）：

| 步骤 | 输入 | 输出 | 负责 | 不负责 |
|---|---|---|---|---|
| 编剧 | 商家资料、案例、场景 | 每格画面描述 + 台词 | 演什么 | 不写产品外形（交给参考图） |
| 生图 | 画面描述 + 参考图 | 分镜图 | 画得对、画得真 | 不画任何文字 |
| 生视频 | 首帧 + 分镜 + 参考图 | 视频 | 怎么动、怎么念 | 不改剧情 |

### 第 4 步 · 每段提示词自包含
- 每次模型调用都是无状态的，**只看得到本段文字 + 本次传入的图**。
- 禁止写「参考上文」「按后台配置」——下游模型根本看不到。

### 第 5 步 · 加校验关卡（Gate）
- 每一步输出后用**程序校验**（格式、字数、字节数、条数），不合格自动重试或降级。
- 校验要放在**花钱最多的步骤之前**：ThinkNova 视频工作台「先审分镜图，再生视频」，就是把关卡放在最贵的一步前面。

### 第 6 步 · 预算与上限
- 每个模型都有输入上限（字数 / 字节 / token），**各模型不同，逐个问清，不套用**。
- 系统不能贴着上限跑：ThinkNova 曾经 videoPrompt 中位数占上限 85%，一半订单要重试。留出余量。

### 第 7 步 · 先单条验证，再铺开
- 改一处 → 跑一单 → 拿**最终产物**验证（不是中间态，不是「配置写进去了」）→ 老板过目 → 才批量铺开。
- 验收要有**修复前基线**，同条件对比。

## 6.3 用 Claude Code / Codex 落地一个 Workflow

### 方式 A · 对话里手动驱动（入门）
```
1. 进入 Plan Mode，让 AI 先调研 + 出方案
2. 你审方案 → 批准
3. AI 按步骤执行，每步汇报「验收什么 + 做了什么」
```

### 方式 B · 固化成 Skill（重复性任务）
把稳定下来的流程写成 `SKILL.md`：
```markdown
---
name: xhs-note
description: 写小红书笔记时使用。四柱：选题→标题→配图→文案。
---
## 步骤
1. 选题：先回答「用户刷到这条的那一秒在找什么」
2. 标题：……
3. 配图：……
4. 文案：……
5. 出稿后必须运行 scripts/check_xhs.py，全部通过才交付
## 交付格式
图片 + 文案.txt（UTF-8 BOM）+ _说明.md
```

### 方式 C · 子 Agent 分工（复杂任务）
- 主 Agent 负责拆解和汇总；子 Agent 各管一块（调研 / 写代码 / 审查）。
- 派子 Agent 时写清「任务书」：目标、输入、输出格式、完成标准、不许做什么。
- **子 Agent 的结论必须自己复核再转述。**

### 方式 D · 无人值守自动化（进阶）
- Claude Code：`claude -p "…"` 无头模式 + 定时任务 / CI；GitHub Actions 集成。
- Codex：`codex exec "…"` 非交互执行；Codex Cloud 后台任务。
- 有副作用的脚本先 `--dry` 演练。

## 6.4 Workflow 设计检查清单

- [ ] 终态定义清楚、可验收
- [ ] 每一步有明确输入/输出/边界
- [ ] 每段提示词自包含
- [ ] 规则是指派式，不是禁令堆
- [ ] 提示词之间不互相冲突
- [ ] 每个模型的输入上限已确认，留有余量
- [ ] 最贵的步骤前有校验/人审
- [ ] 失败有重试和降级策略，且能看到每次尝试的原始报错
- [ ] 先单条验证，用最终产物验收，再铺开
- [ ] 改一处之前列出影响范围

**课后练习**：把你手上一件每周重复的工作，用 6.2 的七步法画成表格。
