# 第 8 课 · 标准用法、反模式与结业考核

---

## 8.1 通用标准工作法（Claude Code / Codex 都适用）

```
① 定终态     这件事做完长什么样？谁验收？
② 读现状     规则文件 → 记忆 → 权威源（线上数据 / 官方文档）
③ 出方案     大任务用 Plan 模式；说清「做什么 + 放弃了什么」
④ 小步执行   改一处 → 验一处
⑤ 用最终产物验收  不是「配置写进去了」，是「真实输出里看到了」
⑥ 汇报       验收了什么 + 做了什么 + 还剩什么
⑦ 沉淀       被纠正的写进记忆；重复的做成 Skill；事故级的做成 Hook / 权限
```

## 8.2 写给 AI 的任务单模板（派活 / 派子 agent 通用）

```
目标：＿＿（一句话，带可验收的终态）
背景：＿＿（为什么做，相关文件 / 链接）
输入：＿＿
输出格式：＿＿（文件名、结构、语言）
完成标准：＿＿（怎么算做完，跑什么验证）
不许做：＿＿（边界）
```

## 8.3 十大反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 一句「帮我优化一下」 | AI 自己猜需求 | 说具体文件、具体目标、验收标准 |
| 一个会话干所有事 | 上下文污染，越来越笨 | 一个任务一个会话 |
| 规则文件越写越长 | 重要规则被稀释、被截断 | 索引 + 下沉，定期瘦身 |
| 只写禁令 | 模型不执行 | 指派式 + 替换项 |
| 加规则不查冲突 | 规则打架，输出不稳 | 加一条前先问挤掉谁、和谁冲突 |
| 记忆只追加不删除 | 新旧结论并存，AI 读到旧的 | 覆盖旧结论，标作废 |
| 「配置改了」就当完成 | 落库 ≠ 送达 | 跑一次看真实输出 |
| 看一帧就下结论 | 结论是假的 | 逐帧 / 全量核验 |
| 直接转述子 agent 结论 | 错误被放大 | 自己复核 |
| 出错就换模型 | 问题没解决 | 先分层排查：上下文？权限？提示词？ |

## 8.4 安全清单

- [ ] 密钥不写进提示词、不写进规则文件、不打印到日志
- [ ] 外发内容前扫一遍密钥特征
- [ ] `bypassPermissions` / `--yolo` 只在一次性容器里用
- [ ] 危险命令（删除、强推、改生产配置）放进 deny 或 ask
- [ ] 有副作用的脚本先 `--dry`
- [ ] 线上配置只改文本内容，结构变更交给技术

## 8.5 结业考核

### 一、概念题（每题用一两句话回答）
1. Agent 和 Workflow 的区别是什么？各举一个 ThinkNova 的例子。
2. Skill 的「渐进式披露」是什么？为什么它让我们能装很多 skill？
3. Harness 负责哪些事？说出至少 5 项。
4. RAG 的标准流程是什么？Agentic Search 和它有什么不同？
5. 为什么「不许删生产数据」不能只写在 CLAUDE.md 里？
6. Codex 的 `approval_policy` 和 `sandbox_mode` 分别管什么？

### 二、实操题
1. 为一个项目写 `CLAUDE.md`（≤60 行）和一份等价的 `AGENTS.md`。
2. 写一个 Skill：`SKILL.md` 要有清晰的触发描述和带验证步骤的流程。
3. 配一个 `PreToolUse` Hook，拦截 `rm -rf`。
4. 用 `claude -p` 或 `codex exec` 写一个一行命令，把某个日志文件里的报错分类汇总。

### 三、ThinkNova 案例题
1. 一单视频 10 次重试、跨 6 个模型都报「台词条数和镜头数不符」。你的第一判断是什么？下一步查什么？
2. 商家反馈「视频里出现了字幕乱码」。按三层职责分工，问题最可能出在哪一层？为什么？
3. 你改了编剧提示词，后台显示保存成功，但成片没变化。列出你的排查步骤。
4. 为「奶茶店新品」写一份 B 叙事档 5 格分镜脚本，并自查：画面是否为台词作证？是否写了产品形态词？是否有字幕？

### 参考答案要点
- 案例题 1：多模型报同一错 → 提示词自相矛盾，不是模型问题；查案例的镜头数设置与全局提示词里关于「多格多句」的假设是否冲突。
- 案例题 2：生图层画了字，被裁进首帧再进视频；查分镜图本身有没有文字、生图提示词有没有「不画任何字」、编剧是否把台词写进了画面描述。
- 案例题 3：① 确认改的字段真的被这条链读取 ② 镜像字段是否双写 ③ 烧一单，拉该单真实提交串看有没有新文案 ④ 量字节是否超上限导致重试 / 降级 ⑤ 看这单是哪个模型、第几次尝试出的。
